# 工人智能评价平台（MVP）

面向施工现场工人的评价与画像前端原型。项目围绕“数据采集 → 指标评分 → 模型执行 → 标签生成 → 工人画像”的最小业务闭环，提供可操作的页面流程、结构化规则配置和演示数据。

> 当前为 React + Vite 前端 MVP，页面中的新增、编辑、执行和确认操作均使用浏览器内存中的模拟数据；刷新页面后会恢复初始演示数据，尚未接入真实后端、文件存储或 AI 服务。

## 已交付功能

## 核心业务口径

### 五维评价

1. 职业资质：年龄、职业证书、项目经验、职业健康等。
2. 履约能力：有效工时、出勤天数、连续缺勤、工作稳定性等。
3. 安全行为：安全培训、奖励、处罚和整改等。
4. 工作效率：有效工时、质量奖励、质量整改等。
5. 信用记录：考勤诚信异常、劳资纠纷、投诉和处罚等。

### 指标评分类型

| 类型 | 规则含义 | 配置重点 |
| --- | --- | --- |
| 基准分 | 进入评价周期即赋予的默认分值。 | 默认基准分。 |
| 加分项 | 计分依据来源满足判定条件时，按指标值和单次加分值累计。 | 计分依据来源、判定条件、单次加分值、最高加分上限。 |
| 扣分项 | 计分依据来源满足判定条件时，按指标值和单次扣分值累计。 | 计分依据来源、判定条件、单次扣分值、最大扣分上限。 |
| 权重计分 | 由计分依据来源值换算完成比例，再计算指标得分。 | 计分依据来源、标准值、最大权重分值。 |

权重计分统一口径为：

```text
指标得分 = 完成比例 × 最大权重分值
完成比例 = 计分依据来源值 / 标准值（按业务规则限制在 0%～100%）
```

指标得分最高不超过“最大权重分值”。该字段不是“维度内权重(%)”。

### 计分依据来源

评价指标从按工人、项目和评价周期生成的评价计算宽表中取值，不直接在评价规则中读取原始表字段。当前前端字典包括：有效证书数量、公司技能大赛获奖次数、有效参与项目数量、体检不合格次数、有效工时占比、当月出勤完成率、近3个月劳务公司变更次数、安全之星奖励次数、安全整改记录次数、质量之星奖励次数、质量整改记录次数、劳资纠纷记录数量；此外保留连续缺勤天数和考勤诚信异常次数以兼容现有演示指标。

原始数据由数据采集中心维护，页面平级展示人员信息、用工信息、考勤信息、班组信息、企业信息，以及体检记录、奖励记录、处罚记录、证书记录和劳资纠纷记录。每个计分依据来源在编辑表单中展示只读的计算口径。

数据采集中心的 AI 链路为“当前业务页签批量上传附件 → Mock 异步识别并填充对应台账字段 → 点击完成并确认 → 结果进入对应台账并标记待确认 → 快捷筛选 → 左右对照弹窗编辑并确认”；AI 识别结果不会跳过确认直接写入台账，也不会直接变为已确认数据。

### 执行链路

```text
实名制 / AI采集 / 人工台账
            ↓
        评价指标取数
            ↓
   五维汇总、等级判定、生成执行批次
            ↓
       执行智能标签规则
            ↓
      更新工人画像与评价摘要
```

## 技术栈

- React 19
- Vite 8
- Tailwind CSS 4
- lucide-react 图标库
- JavaScript（ES Modules）

项目不是 Vue 2。若正式研发必须采用 Vue 2，可复用本项目的业务规则、字段模型、接口约定与交互流程，但需要迁移 React 页面组件。

## 本地运行

### 环境要求

- Node.js 20 或更高版本
- npm 10 或更高版本

### 安装与启动

```bash
npm.cmd install
npm.cmd run dev
```

启动后根据终端输出访问本地地址，默认通常为 `http://localhost:5173`。

### 构建与检查

```bash
npm.cmd run build
npm.cmd run lint
npm.cmd run preview
```

构建产物生成在 `dist/` 目录。

## 前后端对接建议

正式后端建议采用 Spring Boot，并将规则与数据取数解耦：

- **数据提供器策略**：先按工人、项目和评价周期生成评价计算宽表，再向评价规则提供统一的计分依据来源值。
- **评分策略**：分别处理基准分、加分、扣分、权重计分，避免在控制器中堆叠判断。
- **通用规则执行器**：执行指标条件和标签 `AND` / `OR` 条件，返回可追溯的命中依据。
- **异步批次执行模型**：每次模型执行创建批次，记录范围、执行人、状态、成功/失败数量、评分结果和标签结果。

建议优先落地以下业务实体：工人、项目、实名制考勤、人工台账、评价维度、评价指标、模型配置、等级规则、执行批次、执行明细、标签分类、标签规则、工人标签和工人画像快照。

## MVP 边界与后续工作

本版本完成的是可演示、可验证的前端业务闭环，以下内容待后端和基础设施接入后实施：

- 真实实名制系统、考勤系统与项目数据同步；
- 文件上传、OCR / AI 识别服务与识别置信度；
- 表单数据、规则配置和执行记录持久化；
- 权限、数据范围、审计日志和异常重试；
- 大批量模型任务队列、进度查询和失败重跑；
- 真实评价结果、标签命中依据和画像快照的可追溯查询。

首页看板中的考勤、AI、电子合同与评价数据同样是 Mock 聚合结果：实名制/闸机考勤在正式接入后仍是考勤权威来源，AI 仅用于辅助核验；首页 AI 统计只展示“已匹配”和“陌生人”，其中“陌生人”仅表示当前项目人脸库比对无匹配，不等同于风险结论。首页不提供待办、处置、复核、人员明细或跨模块跳转。

首页看板当前采用响应式单屏网格：中部人员与考勤卡片约占三分之二宽度，AI 识别卡片约占三分之一，为较长班组名称预留图例空间，班组图例同一行显示人数与占比；考勤卡片右侧的“今日考勤数据”和“在场班组分布”采用紧凑间距，保持在固定卡片范围内；底部仅保留合同统计和工人评价统计两张卡片，分别展示合同状态/完成签署趋势和 A-D 实心饼图/五维评分，A级占比指标补充 A 级人数说明；在低高度窗口下自动压缩统计区间距，不启用页面纵向滚动。首页仅保留项目选择，统计周期固定为今日，不提供手动刷新。

企业数据看板使用独立的 `enterprise-dashboard` 菜单，顶部通过组织下拉选择全公司或分公司，第一排固定 7 张 KPI，主屏最多展示 5 个项目，项目对比不展示数据状态字段并提供全部项目弹窗；第二排项目对比约占 3/4 宽度，重点关注约占 1/4，主表使用适度字号和行高完整填充 5 行内容。重点关注只显示出勤率最低 3 项和合同签署率最低 3 项，使用红/橙色提醒卡和警示图标，不显示提醒数量或额外提示文字，指标数字放在前面，项目名称右对齐并为蓝色可点击整行穿透，不显示序号和查看按钮；工人库人数 KPI 可跳转工人库；企业工人库左侧展示正式评价 A/B/C/D 环形图并在色块中标注等级，右上角提供进入工人库按钮，右侧以 2×2 卡片展示动态标签人数且卡片可携带对应标签筛选跳转工人库，卡片高度与企业用工趋势统一，不展示当前在场、历史工人和累计合作工人；企业用工趋势使用 React + SVG 实现参考 ECharts 的企业数据图表视觉：独立浅灰画布、弱网格、双 Y 轴、渐变蓝色柱、紫色折线、日期、悬浮十字线和 Tooltip，支持底部图例切换单独查看人数柱状图或出勤率折线图；不常驻展示人数或出勤率数字，所有具体指标通过悬浮 Tooltip 统一查看；底部不保留更新时间行，不建设合同、评价、AI 运行摘要大卡片。

数据采集中心当前采用横向底部线条 Tab 样式：十个业务页签平级展示，五类业务记录页签的按钮和查询分行展示，各自提供“AI智能采集”按钮；列表支持勾选“仅看待确认”筛选、附件点击预览和左右对照确认弹窗，不新增左侧菜单或路由。AI 上传 Mock 支持 PDF、Word、PNG，单文件不超过 20MB、批次总大小不超过 100MB；识别结果先在上传抽屉中暂存，点击“完成”并确认后才写入对应台账；批量上传多个文件时会模拟 1 个识别失败文件，便于演示失败处理流程。刷新页面后恢复初始数据。

## 验收建议

1. 在数据采集中心确认一条 AI 识别记录，检查其是否进入对应人工台账。
2. 在指标配置中新增四类任一评分规则，验证计分依据来源、计算口径和算分规则校验。
3. 在评价维度页签调整权重，确认草稿状态、保存按钮和合计100%校验均生效。
4. 将模型维度权重调整为合计 100%，执行一次指定项目评价，检查批次记录、评分结果及标签执行结果。
5. 新增一条含多条件 `AND` 或 `OR` 的标签规则，在标签管理和工人画像中核对展示结果。
6. 从工人库进入画像详情，检查五维雷达、综合评价、履历和五类台账是否完整展示。
7. 打开企业数据看板，检查组织下拉、7 张 KPI、5 行项目对比、全部项目弹窗、重点关注红橙提醒卡、企业工人库等级标注和近 7 日/近 15 日趋势 Tooltip；点击工人库人数 KPI 与“进入工人库”按钮检查默认进入工人库，点击任一标签人数卡检查进入工人库后自动选中对应标签；点击项目表和重点关注任意项目行检查是否穿透到项目首页并自动选中项目。再检查首页项目切换、趋势图和 A-D 等级；在 1440 × 900 与 1280 × 760 下确认两个看板内容区不出现纵向滚动条。
